# Test fixtures

Non-personal images generated locally; CI needs no encoder.

- `tiny.heic`: 64×48 solid red, HEVC. `magick -size 64x48 xc:red /tmp/issue17-tiny.png && heif-enc --hevc -q 85 -o tiny.heic /tmp/issue17-tiny.png`
- `rotated.heic`: 64×48 red with a 16×16 blue square at the top-left, encoded with `--rotate-cw 90` so the decoded image is 48×64 with the blue square at the top-right (proves the decoder applies the HEIF rotation transform). `magick -size 64x48 xc:red -fill blue -draw 'rectangle 0,0 15,15' /tmp/issue17-oriented.png && heif-enc --hevc --rotate-cw 90 -q 85 -o rotated.heic /tmp/issue17-oriented.png`

Tools: ImageMagick `7.1.2-35`, libheif `heif-enc 1.23.7` (Homebrew), 2026-11-03.
- `gps.heic`: `tiny.heic` with a GPS IFD added, at the plan's public fixture point (the Statue of Liberty, 40.689247 N, 74.044502 W); proves the HEIC Exif item is read (photo GPS, plan 2026-11-06-photo-gps-places B2). It carries no other new tags (no make, model, date or owner). `exiftool -GPSLatitude=40.689247 -GPSLatitudeRef=N -GPSLongitude=74.044502 -GPSLongitudeRef=W -o __tests__/fixtures/gps.heic __tests__/fixtures/tiny.heic` with ExifTool `13.55` (Homebrew), 2026-11-06. The GPS JPEGs (refs, zeros, missing refs, the late-EXIF file) are made in memory by `__tests__/lib/photo-gps.test.ts` with sharp `withExif`, so they are not files here.
- `anim.gif`: two 32×32 frames (red, blue), loops; proves animated GIF output keeps its frames. `magick -size 32x32 xc:red xc:blue -set delay 20 -loop 0 anim.gif`
- `noise.png`: 1000×1000 random noise; its JPEG at q72 and q60 both exceed 350 KB, which is the thumbnail `too_large` case. `magick -size 1000x1000 xc:gray +noise Random -depth 8 noise.png`
- `anim-portrait.gif`: two 40×400 frames; proves the long-edge cap applies to a portrait animation (per-frame height). `magick -size 40x400 xc:red xc:blue -set delay 20 -loop 0 anim-portrait.gif`
- `anim-400.gif`: 400 identical 1×1 frames; over the 300-frame cap (issue #45). `magick -size 1x1 xc:red -duplicate 399 -set delay 5 -loop 0 anim-400.gif`
- `anim-400x10.gif`: 400 identical 10×10 frames (a 40,000-pixel strip); proves the pixel ceiling counts the whole strip of an animation. `magick -size 10x10 xc:blue -duplicate 399 -set delay 5 -loop 0 anim-400x10.gif`
- Video location fixtures (plan 2026-11-06-mcp-attach-media §9, PR 3). Synthetic by Rob's choice (2026-11-07: no openly licensed real iPhone camera original was available, and a re-shared phone clip carried no location key), all 16×16 single-colour 1 s H.264 clips with no make, model, date, encoder or owner tags, at the plan's public fixture point (the Statue of Liberty):
  - `location-mdta.mov`: QuickTime (`ftyp`, `wide`, `mdat`, then `moov`), with ffmpeg's `use_metadata_tags` placing the location in the FullBox `moov/udta/meta` under an `mdta` handler as `keys`/`ilst` item `com.apple.quicktime.location.ISO6709` = `+40.6892-074.0445/` (Apple's QuickTime metadata key); a real iPhone writes `moov/meta` directly, covered by hand-built boxes in `__tests__/lib/video-gps.test.ts`, and the parser prefers direct `moov/meta`, then `udta/meta`, then `©xyz`. `ffmpeg -f lavfi -i "color=c=red:size=16x16:rate=2:duration=1" -c:v libx264 -pix_fmt yuv420p -f mov -map_metadata -1 -fflags +bitexact -flags:v +bitexact -movflags use_metadata_tags -metadata "com.apple.quicktime.location.ISO6709=+40.6892-074.0445/" location-mdta.mov`
  - `location-xyz.mp4`: MP4 with `moov` before `mdat` and the location in `moov/udta/©xyz` (the Android layout) = `40.689247, -74.044502`. `ffmpeg -f lavfi -i "color=c=blue:size=16x16:rate=2:duration=1" -c:v libx264 -pix_fmt yuv420p -map_metadata -1 -fflags +bitexact -flags:v +bitexact location-xyz.mp4 && exiftool -overwrite_original -UserData:GPSCoordinates="40.689247, -74.044502" location-xyz.mp4`
  - `no-location.mov`: the same QuickTime recipe in green with no location metadata at all (the `absent` case). `ffmpeg -f lavfi -i "color=c=green:size=16x16:rate=2:duration=1" -c:v libx264 -pix_fmt yuv420p -f mov -map_metadata -1 -fflags +bitexact -flags:v +bitexact no-location.mov`

  Checked with `exiftool -n -G1 -a -s`: only `Keys:GPSCoordinates` (mdta) or `UserData:GPSCoordinates` (©xyz) is present, and nothing in `no-location.mov`. Edge cases (64-bit box sizes, size 0 to end of file, out-of-range values, structural limits) are built in memory by `__tests__/lib/video-gps.test.ts`. Tools: ffmpeg `9.0.2`, ExifTool `13.55` (Homebrew), 2026-11-07.
- Video track fixtures (video-posters plan, Task 2: `lib/video-track.ts` reads the pixel size and HDR transfer; Task 4 decodes the same files with the real ffmpeg binary). Synthetic single-colour 1 s clips at 2 fps, with no make, model, date, location or owner tags. The colour tags go on the frames with `setparams`: ffmpeg 9's `-color_primaries`/`-color_trc` output options were overridden by the untagged frames, and the stream came out `unknown` with no `colr` box. `__tests__/lib/video-track.test.ts` reads each `colr` payload from the file's bytes, so a recipe that stops writing one fails the test.
  - `track-sdr-nclc.mov`: QuickTime (`ftyp`, `wide`, `mdat`, then `moov`), H.264 `avc1` 48×32, `colr` `nclc` 1/1/1 (BT.709 primaries, transfer and matrix; payload `6e636c63 0001 0001 0001`). 1,537 bytes. `ffmpeg -f lavfi -i "color=c=0x3080c0:size=48x32:rate=2:duration=1" -vf "setparams=range=tv:color_primaries=bt709:color_trc=bt709:colorspace=bt709" -c:v libx264 -pix_fmt yuv420p -f mov -map_metadata -1 -fflags +bitexact -flags:v +bitexact track-sdr-nclc.mov`
  - `track-hlg-nclx.mp4`: MP4 (`mdat` before `moov`), 10-bit HEVC `hvc1` 64×36, mid-grey, `colr` `nclx` 9/18/9 with full_range 0 (BT.2020 primaries, ARIB STD-B67 HLG transfer, BT.2020 non-constant matrix, limited range; payload `6e636c78 0009 0012 0009 00`). 969 bytes. `ffmpeg -f lavfi -i "color=c=0x808080:size=64x36:rate=2:duration=1" -vf "setparams=range=tv:color_primaries=bt2020:color_trc=arib-std-b67:colorspace=bt2020nc" -c:v libx265 -x265-params log-level=error:info=0 -pix_fmt yuv420p10le -tag:v hvc1 -map_metadata -1 -fflags +bitexact -flags:v +bitexact track-hlg-nclx.mp4`
  - `track-hlg-nclc.mov`: the same HLG clip as QuickTime (`mdat` before `moov`, the iPhone layout), `colr` `nclc` 9/18/9 (payload `6e636c63 0009 0012 0009`). 923 bytes. The same command with `-f mov` before the output name `track-hlg-nclc.mov`.
  - No `colr`: `no-location.mov` above (H.264 16×16, no colour tags), whose transfer reads as `unknown`.
  - `audio-only.m4a`: no video track (one `soun` track, AAC 8 kHz mono, 0.25 s). 1,732 bytes. `ffmpeg -f lavfi -i "sine=frequency=440:sample_rate=8000:duration=0.25" -c:a aac -b:a 16k -map_metadata -1 -fflags +bitexact -flags:a +bitexact audio-only.m4a`

  Both HEVC clips decode with Homebrew ffmpeg and with the `ffmpeg-static` 6.0 binary. Truncated sample descriptions, PQ (transfer 16), ICC `colr`, QuickTime colour tables and the full transfer table are built in memory by `__tests__/lib/video-track.test.ts`. Tools: ffmpeg `9.0.2_1` with x264 `r3222` and x265 `4.3` (Homebrew), 2026-11-08.
