Using this page with Claude

This page is a review board with its own database. Claude loads drafts into it, people edit and approve them here, and Claude reads the approved ones back and pushes them to the destination system through that system's MCP tools. Copy the instructions below into the Claude session that owns this page.

Who can edit

  • Reviewers need to be signed in to claude.ai and invited from the Share menu as Editors. While the page also has a public link, outside editors can't save.
  • Viewers can read the drafts but can't change them.

Instructions for Claude

This artifact is a bulk review board. Its database holds:
  collection "records"  one document per draft record
  doc "config/page"     optional page settings

SET UP (once)
  Publish this HTML file with the Artifact tool, declaring capabilities
  {"db": {}, "user": {"scopes": ["profile"]}}. Share it from the Share menu
  with each reviewer as an Editor. Every read and write below goes through
  ArtifactData with that artifact's url. Load the destination's MCP tools
  and read its docs before pushing anything.

LOAD DRAFTS
1. Publish each record's media with this page (Artifact publish, `files`):
   images at img/<fileId>.jpg, video posters at img/<fileId>.jpg,
   playable video at vid/<fileId>.mp4 (H.264, 1280px max). The page can
   only show files published with it or data: URLs; outside image hosts
   are blocked.
2. Write one document per record to "records" with ArtifactData "batch"
   (up to 50 per call). Doc id: a short slug, e.g. "2021-05-31-caboose".
3. Optionally write "config/page" to rename the page and its fields.

RECORD SCHEMA (records/<id>)
  order       string   sort key, e.g. "2021-05-31 11:21"; "1000-01" sorts early
  group       string   label for the jump strip, e.g. "2021" or "Old prints"
                       (default: first 4 characters of order)
  title       string
  body        string   the main text
  date        string   free text, e.g. "Summer 1985?"
  place       string   town/landmark level; never a street address
  people      string   comma list of who appears
  visibility  string   one of config.visibilityOptions values (default PUBLIC)
  notes       string   reviewer notes for whoever pushes
  questions   string[] things the reviewer should confirm
  why         string   why these files were grouped
  items       array of {
                id, file, type: "photo"|"video"|"file",
                local: "YYYY-MM-DD HH:MM" or null, caption,
                src: "img/<id>.jpg", poster?, video?: "vid/<id>.mp4",
                duration?, excluded: false }
  status      "draft" | "approved" | "revisit" | "skip"
  original    {title, body, date, place, visibility}  your first draft, for "put back"
  sync        {state: "sent"|"error", remoteId, at, message}  written by Claude only
The page writes: updatedAt, updatedBy, statusAt, statusBy (viewer ids).

CONFIG (config/page, all optional)
  eyebrow, title, intro      header text
  labels {title, body, date, place, people, visibility, notes}
  hide   ["people", "visibility", ...]   fields to hide
  visibilityOptions [{value, label}]     default PUBLIC / FAMILY / PRIVATE

PUSH APPROVED RECORDS
1. List "records" (ArtifactData list, out_dir) and take status == "approved"
   whose sync.state is not "sent". Never push draft, revisit or skip.
2. For each: create it in the destination with that system's MCP tools,
   attach every item where excluded is false (original files, not the
   resized copies), then apply the approval/consent step the destination
   requires, only as the account owner has authorised.
3. Update the record: sync = {state:"sent", remoteId, at:<ISO time>}, pinned
   with if_version. On failure: {state:"error", message}. A record with a
   remoteId is updated in the destination, never created twice.
4. Report counts: sent, failed, still waiting for review.
