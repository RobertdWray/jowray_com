# Code layout and house rules

Adapted from the EmpathIQ conventions for this repo's root-level `app/` directory (no `src/`; `@/*` maps to the repo root).

## Layers and import direction

```
app/            routes, pages, Server Functions, route handlers (thin; call features)
features/       use cases (createSubmission, recordMedia, confirm; invite creation and the read-only prefill lookup in `features/invites`; the photo GPS step `features/media/extract-photo-gps.ts`; place lookups `features/places`: the cached, throttled `lookupPlace` and the MCP `suggestPlacesForMemory`; video posters: the claim-and-publish protocol every derived copy shares `features/memories/derived-claims.ts`, the poster step `features/memories/derive-poster.ts` (one POSTER frame per READY video) and the family alert's preview loader `features/memories/admin-previews.ts`); import services and lib
services/       interfaces + factories (storage, email, images, places (the reverse geocoder, `services/places`), video frames (the poster frame service over ffmpeg, `services/video-frames`); the two email templates share `services/email/templates/shared.ts`); import integrations
integrations/   vendor clients (Vercel Blob, SendGrid, sharp + libheif WASM, OpenStreetMap Nominatim `integrations/nominatim`, the no-network place stub `integrations/places-stub`, the loopback frame server and ffmpeg runner `integrations/video-frames`); import nothing above them
server/         db client, env sub-schemas (server-only leaves)
lib/            helpers with no layer above them: logger, validations, claim tokens, invite tokens (`lib/invite-token.ts`), share-form prefill rules (`lib/share-prefill.ts`), replay options (`lib/sentry/replay-options.ts`), media types, site URL (storage and derived prefixes), family contact address (footer, confirmation copy), the `sourceInput` → `source` + `sourceRef` derivation shared by `scripts/draft-memory.ts` and the MCP `draft_memory` tool (`lib/source-input.ts`), derived keys, image-derive error, HEIC worker thread, email assets (generated base64 PNG brand marks; `scripts/make-email-assets.ts` regenerates them), README diagram helpers (find README.md's Mermaid blocks for `scripts/make-readme-diagrams.ts`, which renders `public/diagrams/`, and for the drift test; the SVG safety check both run), photo GPS reading with ExifReader for the browser and the server (`lib/photo-gps.ts`), places helpers (`lib/places`: label rules, timing, errors, result types, and the browser's suggest client and queue), the MP4/QuickTime box walk that video location and video posters share (`lib/mp4-boxes.ts`), a video's first track size and HDR transfer (`lib/video-track.ts`), the poster frame constants, error codes and loopback-URL redaction (`lib/video-frames.ts`), the server Http integration's options (`lib/sentry/http-options.ts`) (some are server-only)
```

- `app/ → features/ → services/ → integrations/`. A layer imports only from layers below it plus `lib/` and `server/`. Nothing imports from `app/`. Pages and Server Functions call `features/`; route handlers under `app/api/` may also call `services/` directly (they are the HTTP adapter layer); nothing in `app/` imports `integrations/`. `eslint.config.mjs` enforces this with `no-restricted-imports`. One exception: `integrations/*` may import **types** from `services/*/types` (they implement those interfaces); value imports stay forbidden.
- `app/_components/` holds shared visitor-facing UI (header, footer, hearts, buttons, field classes). It is a Next.js private folder (not a route), imported only from `app/**` with relative paths, and it never imports `@/server`, `@/integrations` or `server-only` because Client Components use it; `eslint.config.mjs` applies the client-component import rule to it.
- `integrations/*`, `server/*` and anything that reads secrets start with `import "server-only"`. Tests import them through the Vitest alias to `__tests__/stubs/server-only.ts`.
- The ffmpeg binary (`ffmpeg-static`, about 80 MB on Linux) is traced into `/api/upload`, `/api/mcp` and `/api/cron/reconcile-uploads` only (video-posters plan D1). So `features/memories/derive-poster.ts` and `services/video-frames` are imported only from those three entry points (`app/api/upload/route.ts`, `features/admin/attach-media.ts`, which only `app/api/mcp/tools.ts` imports, and the cron route), never from a module a page or its Server Functions can reach: not `features/memories/ingest-upload.ts`, `features/memories/notify-admins.ts` or `features/memories/admin-previews.ts`. `scripts/check-traces.ts` fails the build when the binary or any `ffmpeg-static` file reaches another function.
- Client Components (by convention `*-form.tsx`, `*-client.tsx`, `recorder.ts`, `use-*.ts` hooks, `app/global-error.tsx`, `instrumentation-client.ts`) never import `@/server` or `@/integrations`; they call Server Functions.
- Server code logs with Pino (`lib/logger`), never `console.log`. Contributor fields are no longer redacted (Rob, 2026-11-07, R13): email, name, phone, contributor content and coordinates are allowed in Vercel logs and Sentry Logs. The logger redacts bearer fields only: `SECRET_FIELD_KEYS` except `key`, plus `token` — currently `claimToken`, `claimTokens`, `claimLink`, `ticket`, `clientPayload`, `sig`, `presignedUrl`, `shareUrl`, `inviteToken`, `token` — at the top level and up to three levels down (Pino wildcards are one level each). It also redacts the protected headers `cookie`, `authorization`, `x-vercel-protection-bypass`, `x-vercel-signature` and `next-router-state-tree` in the configured header paths. `redactPii` retains its name but now applies bearer/header redaction to Sentry extra; `key` stays visible in Pino for non-secret setting names, while Sentry still filters that field. Never put bearer values in free-text log messages. Log ids (`memoryId`, `mediaId`), never Prisma rows or people.
- Route handlers validate input with zod schemas from `lib/validations` and answer `{ success, data }` or `{ error: { code, message } }`.

## Cache Components rule (replaces EmpathIQ's `force-dynamic` rule)

Next.js 16 with `cacheComponents: true` prerenders whatever it can at build time. A build runs with no database and no `.env`, so:

- Never export `dynamic`, `runtime`, `revalidate` or `fetchCache` from a route file.
- The **first** thing a dynamic page component does is `await connection()` (then `params`/`searchParams`/`headers()` as needed); a `GET` handler reads `request.headers` or `request.nextUrl` first. Only then touch Prisma or env. `await params` by itself is not enough: a runtime prefetch prerender knows the URL, and the Neon driver's `randomBytes` on connect then fails the prerender (seen on `/m/[claimToken]`, 2026-11-03).
- `maxDuration` is allowed; for Server Functions it is set on the page that hosts them.
- Never construct a `PrismaClient` or parse env at module scope. Use `getDb()` and the lazy `getXEnv()` accessors in `server/config/env.ts`, each of which parses on first call.
- Each task adds only its own env sub-schema to `server/config/env.ts`; booleans parse strictly (`"true"` / `"false"`), lists are split, trimmed and lower-cased.

## Sentry (alpha data policy, 2026-11-04)

- `lib/sentry/data-collection.ts` is the one data policy for both inits. Rob, 2026-11-04: "I have deliberately authorized and pushed for 100 % tracking and error data collection. The family has approved these aggressive tracking measures since it is an alpha, vibe-coded website and only family will be using it. Intensive logging to rapidly fix errors is more important than security and privacy." It supersedes the Phase 1 "everything off, Replay off" policy. Plan and rulings: `docs/plans/2026-11-04-sentry-full-telemetry.md` (§2a, §3).
- Allowed in Sentry: contributor and invitee names and emails (R10), contributor email and name as user context, Server Function inputs and outputs, headers, Prisma query data, stack-frame locals, unmasked replays. Still forbidden everywhere: claim tokens in any form (`/m/<token>`, `?t=`, `claimToken(s)`, `claimLink`), invite tokens and share URLs in any form (`/s/<token>`, `inviteToken`, `shareUrl`), upload tickets (`ticket`, `clientPayload`, `sig`) and the values of `cookie`, `authorization`, `x-vercel-protection-bypass`, `x-vercel-signature`. The names live in `lib/sentry/secrets.ts`; `lib/sentry/scrub.ts` removes them from every event, span, log, breadcrumb, context and replay custom event; `__tests__/lib/sentry-envelope.test.ts` runs the real server SDK with the policy and proves no synthetic `SENTRYTEST_` token leaves while the user email does. Accepted residuals: the `/m/<token>` page URL inside replay DOM recordings and user-taken feedback screenshots (Rob, 2026-11-04), plus the `/s/<token>` page URL inside replay DOM recordings (R5) and Vercel request logs (R11, like `/m/`; Rob, 2026-11-07).
- The tunnel is in handler mode: `app/sentry-tunnel/route.ts` re-exports the SDK's `POST`, and `tunnelRoute: "/sentry-tunnel"` in `next.config.ts` names it. A healthy build log contains `[@sentry/nextjs] The tunnel route sends events through app/sentry-tunnel/route.ts.`; rewrite mode would drop browser events on protected previews (SDK 11.9+).
- Pino keeps `[Redacted]` for bearer fields and protected headers; contributor fields pass through under R13. Sentry Logs carry `user.email` automatically once the user is set.
- Server-side Data Scrubber and Default Scrubbers for the `jowray_com` project are **off** since 2026-11-08 (S1, Rob's go-ahead after PR-2 went live and its token checks passed; evidence `docs/plans/evidence/2026-11-notify/post-merge.md`). Ordinary event text such as a story containing "author" is no longer replaced with `[Filtered]`. The SDK scrubber (`lib/sentry/scrub.ts`) is now the only token control, so never weaken it. Rollback: set `dataScrubber` and `dataScrubberDefaults` back to `true`. Procedure: `docs/plans/2026-11-07-notify-correspondents.md` §8.10.
- Browser (`instrumentation-client.ts`): 100 % traces and Session Replay (text, non-password inputs, media, placeholders and `title`/`aria-label` unmasked via `lib/sentry/replay-options.ts`, `maskAttributes: []`; password inputs stay masked), replay network bodies for same-origin requests (scrubbed by `scrubRecordingEvent`), the floating "Report a problem" feedback button (styled from `#sentry-feedback` in `app/globals.css`; name and email pre-filled from the identified contributor; screenshots on), browser profiling (`Document-Policy: js-profiling` on every response from `next.config.ts`; Chromium only), the third-party error filter in tag mode (`applicationKey: "jowray_com"`), React component annotation and widened source-map upload. `app/global-error.tsx` shows the crash-report dialog. Server (`instrumentation.ts`): its Http integration replaces the SDK's default one, so `lib/sentry/http-options.ts` keeps that default's `disableIncomingRequestSpans: true` and also ignores the poster frame server's loopback `/__frames/` requests; every Server Function is wrapped by `instrumentedAction`, `afterWithFlush(name, cb)` groups deferred work into one `task` span, the reconcile cron reports explicit check-ins (production only) with every item in its own isolation scope. Node profiling is deferred (no Node 26 binary). If a Content-Security-Policy is ever added, Replay needs `worker-src 'self' blob:` and the tunnel needs `connect-src 'self'`.
- Identity: `lib/sentry/user.ts`. `user.email` is the key, `user.username` the name, `user.id` the contributor id when known; `memory_id`, `media_id` and `submission_id` are tags (`tagIds`), never `user.id`. Set only where the contributor row is already loaded; in the browser from the remembered contributor, the typed fields and the loaded memory. An invite lookup never identifies; the share form skips mount identification when the invite supplies the identity and the remembered email differs (D4). Swallowed browser errors go through `reportClientError` (`lib/sentry/report.ts`) with `surface` and `step` tags.

## Checks

`npm run validate` (= `next typegen && tsc --noEmit`, then `eslint`), `npm run test:run`, `npm run build:offline` (the build behind `scripts/no-network.mjs`, which refuses non-loopback sockets and DNS lookups on the main thread of every Node process in the build; worker threads and native code are outside it, so it is a strong check, not a proof — `__tests__/scripts/no-network.test.ts` pins its behaviour). All three pass with `DATABASE_URL` unset and no `.env*` file; fonts come from the Fontsource packages. `npm run build` (and so `build:offline`) ends with `tsx scripts/check-traces.ts`, which reads every function's `.nft.json` trace and fails the build unless the ffmpeg binary matches its pinned SHA-256 for the build platform, it is traced into exactly `/api/upload`, `/api/mcp` and `/api/cron/reconcile-uploads`, no other function carries an `ffmpeg-static` file (through its own trace or the files every function shares), and no function's traced files, with those shared files, pass 220 MB (`docs/dependencies.md`). `FFMPEG_BIN`, `FFMPEG_BINARIES_URL` and `FFMPEG_BINARY_RELEASE` are never set.

`npm audit` is not clean on purpose and every `--force` fix it offers is a downgrade; the overrides in `package.json` and the accepted advisory are explained in `docs/dependencies.md`. Never run `npm audit fix --force`.

## Rules every agent follows

- Every change goes on a branch with a PR.
- No `eslint-disable` without Rob's all-caps "YES". No band-aids: fix the root cause.
- No git submodules. Never commit `.env*`. Never print secret values.
